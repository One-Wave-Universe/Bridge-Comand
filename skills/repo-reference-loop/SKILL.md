# Repo Reference Loop Skill

Use for any One-Wave task that can change architecture, science, builds, bridges, or documentation.

## Loop
REFERENCE GIT -> ASK/PIVOT -> REFERENCE METADATA/CENTER-FLIP -> VALIDATE/PIVOT -> UPDATE GIT/CENTER-FLIP -> REFERENCE.

Rules:
- Start from the owning repository's canonical start/reference files.
- Do not invent parallel doctrine from chat memory.
- Every new external answer is compared against repository authority before adoption.
- Every flip returns to center/reference.
- Distinguish established, implemented, tested, unverified, hypothesis, failed, and blocked.
- Change one thing at a time when diagnosing.
- After three repeats of the same failure, switch diagnostic angle or transport.
- A receipt must prove the endpoint requested, not merely an intermediate queue.
- Update the owning repo with durable decisions; keep Bridge-Comand limited to bridge/relay/control contracts.
